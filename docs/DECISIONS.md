# Implementation decisions

This log records owner-scoped choices made while implementing [PLAN.md](PLAN.md).
The goal remains the complete plan, including its release and real-world acceptance gates.
Decisions are implemented provisionally unless a row says otherwise; they do not replace acceptance evidence.

| ID | Date | Decision | Reason and consequence |
| --- | --- | --- | --- |
| D001 | 2026-09-09 | New projects use the CadQuery contract. Existing projects require an explicit migration and retain their original files and reports. | The application contains substantial legacy inch-based designs. Silently interpreting them as millimeter CadQuery projects would corrupt meaning. A clearly identified legacy viewer remains available during migration. |
| D002 | 2026-09-09 | Store the runtime contract in `stud.json`, versioned records in `records/`, checkpoint summaries in `checkpoints/`, durable local coordination in `.stud/`, and immutable packets in `exports/`. | Keeps full-folder copies portable and separates recovery data from disposable artifacts. No global design or pricing database. |
| D003 | 2026-09-09 | Use a local coordinator with a project-wide process lock; agent commands return an isolated request workspace. | One source writer per project, with read-only comparison and durable record writes available concurrently. External Git changes produce conflicts. |
| D004 | 2026-09-09 | Use millimeters in model geometry, with an imperial display option and US Letter as the initial home-printer default; also support A4. | Matches the plan's geometric contract and initial DIY use. Every packet states scale and includes a physical scale-check mark. |
| D005 | 2026-09-09 | Keep actual macOS/Windows installation, signed update, and DIY-reader checks as explicit acceptance gates. Verify print quality directly in the PDFs. | User clarification waives physical printing: check vector scale, geometric dimensions, page bounds, clipping and readable rendered pages. Native/release evidence remains separate from generated configuration. |
| D006 | 2026-09-09 | Preserve the existing viewer UI, layout, styling, controls, inspection flow, and liked animation. Integrate the new model/events beneath those surfaces. | Explicit owner requirement: “I worked hard on the UI of the viewer, I'm expecting that to be maintained.” Baseline screenshots and the running animation are archived under `docs/evidence/`; verify integration visually against them. Any required history/plan controls must fit the existing design. |
| D007 | 2026-09-09 | Price each concrete purchase specification, including board length. Pool compatible demands before pack rounding; apply a quantity override once per purchase line. | Different stock lengths are different purchases. Product-wide overrides are accepted only when a product has one purchase specification; ambiguous cases require the particular line. |
| D008 | 2026-09-09 | Bundle Git with the desktop runtime using checksum-pinned GitHub Desktop distributions, retaining upstream licenses. | Clean installations need Git for local history and worktrees without relying on a developer toolchain. The pinned bundles and hashes come from the [upstream release](https://github.com/desktop/dugite-native/releases/tag/v2.53.0-4). |
| D009 | 2026-09-09 | Historical exports prefer the exact saved execution. When that archive must be regenerated, compare geometric and authored evidence before accepting it. | Source identity alone cannot guarantee reproducibility for Python with undeclared environment, clock, network, or random inputs. Different regenerated results remain inspectable but cannot silently become the original checkpoint's packet. |
| D010 | 2026-09-09 | Reopen full-folder copies against their own path, repair only local coordination paths and Git worktree links, and retain immutable records and artifact bytes. | A copied endpoint must not reconnect to the original project's coordinator. Stored paths are parsed independently of the host OS; native evidence from a different runtime stays archived evidence. |
| D011 | 2026-09-09 | Keep a supported `stud stop` command for coordinators started by CLI commands. | Detached project processes hold the desktop update lock. Stopping preserves drafts and saved outputs while allowing runtime replacement. |
| D012 | 2026-09-09 | Detailed framing uses native interference checks, actual rectangular stock frames, and explicit cut operations. Site-dependent connections remain unfinished packet findings. | The shed interference check found a real tie/blocking overlap; the implemented housings remove it. Passing geometric checks does not fill missing foundation, uplift, load-sizing, or weatherproofing details. |
| D013 | 2026-09-09 | Use eight hexadecimal digits in default part marks, retaining explicit authored marks where provided. | Building workloads make collisions in five-digit marks too likely. Marks remain derived from persistent object identity; a collision is still rejected. |
| D014 | 2026-09-09 | Measure support as opposing contact area projected perpendicular to a declared bearing direction, defaulting to world downward. Check panel backing continuously along native perimeter edges, including cutouts. | Side contact cannot prove downward bearing; sparse contact samples cannot prove that a panel seam is backed along its length. These are geometric checks, not load-capacity calculations. |
| D015 | 2026-09-09 | Reconcile physical blanks, purchased stock sections, sheet sizes/thicknesses, part quantities and connection hardware before declaring quantities or a packet complete. | Independent review showed that disconnected but individually plausible records could otherwise print an under-purchased cutting plan. |
| D016 | 2026-09-09 | Add version management as a report page using the existing styles; keep the main viewer layout and controls. Historical inspection displays its original saved estimate, with editing available after returning to the current design. | This preserves the owner's existing viewer and prevents old reports from silently changing when project quotes change. |
| D017 | 2026-09-09 | Use compact workshop packets by default: group identical native cut recipes, repeated board allocations, sheet layouts and assembly instructions, and share drawing sheets. | Owner feedback: “That’s way too many pages for a shed.” The 66-page expansion is unsuitable as the standard deliverable. Compact C-labels identify fabrication types within the fixed packet; its CSV and manifest retain the exact mapping to persistent objects and original marks. An expanded layout remains available when explicitly requested. |
| D018 | 2026-09-09 | Remove legacy project and record migration from the implementation and acceptance scope. This supersedes D001's migration requirement. | Explicit owner correction: “We don't need to migrate anything. Sorry that was my mistake”. The newly added migration implementation was removed. Existing format detection and established legacy behavior remain; no project conversion is required. |

Implementation details and verification progress belong in [IMPLEMENTATION.md](IMPLEMENTATION.md).
